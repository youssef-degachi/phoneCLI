# Rove Security Specification

## 1. Authentication & Session Management
- **PIN Auth**: Single PIN required for access. Verified via bcrypt with a cost factor of 10.
- **JWT tokens**: Issued upon successful PIN entry.
    - Secret must be at least 32 characters, stored in `.env`.
    - Expiry: 7 days.
    - Stored in `httpOnly`, `secure` cookies to prevent XSS-based theft.
- **Rate Limiting**: Max 5 login attempts per minute per IP to prevent brute-force.

## 2. Transport Security
- **Cloudflare Tunnel**: All external traffic is routed through Cloudflare, providing HTTPS termination and hiding the local IP.
- **CORS**: Restricted to the assigned `*.trycloudflare.com` domain.
- **Helmet**: Basic security headers (`X-Frame-Options`, `Content-Security-Policy`, etc.) configured via `@fastify/helmet`.

## 3. File System Security
- **Scoped Access**: All file operations (listing, reading) are restricted to `allowedPaths` defined in `rove.config.json`.
- **Traversal Prevention**: Every requested path is resolved and checked using `startsWith()` against allowed roots.
- **Read-Only**: In v1, the file browser is strictly read-only to prevent unauthorized code injection.

## 4. Terminal Security
- **JWT Handshake**: WebSocket upgrades for terminal access require a valid JWT in the query string or cookie.
- **Session Limits**: Max 5 concurrent terminal sessions per project.
- **Shell Restriction**: Only `/bin/bash` or the user's `$SHELL` is allowed.

## 5. AI Safety
- **Confirm-Before-Action**: No command generated by the AI is executed without explicit user confirmation in the UI.
- **Local execution**: Ollama runs locally; no code or terminal output is sent to external AI providers unless explicitly configured by the user.

## 6. Process Safety
- **Child Processes**: Dev servers run as child processes. SIGTERM and SIGKILL are used for clean shutdown.
- **PM2**: The Rove server itself is managed by PM2 to ensure restart on crash without user intervention.
